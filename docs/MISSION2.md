=== P6 : IDENTITÉ, RÉSEAU SÉCURISÉ, NOUVEAUX CONTACTS PAR IP ===
Remplace le protocole actuel (HELLO en clair, sans cadrage) par un protocole authentifié :
- Cadrage : longueur 4 octets (big-endian) + JSON UTF-8, 1 Mo max pour le contrôle ; trames binaires pour les fichiers (jamais de base64). TLS (SslStream) avec certificat auto-signé généré depuis la clé d'identité (aller-retour PFX en mémoire sous Windows) ; la validation compare l'empreinte de la clé publique du certificat à l'identifiant attendu et ignore la chaîne d'autorité.
- Authentification par DÉFI-RÉPONSE (nonce) : à la connexion chaque côté envoie un nonce aléatoire de 32 octets ; l'autre le signe (ECDSA P-256, avec l'identifiant et le nonce de l'autre dans le message signé, pour interdire le rejeu) ; l'identifiant annoncé doit égaler le hash de la clé publique reçue. Sans preuve valide, la connexion est fermée et aucune donnée n'est traitée. Chaque message est SIGNÉ par son auteur sur les octets exacts du JSON ; on stocke et vérifie ce JSON tel quel. Un message dont l'auteur ne correspond pas à la clé authentifiée est rejeté. Supprime l'acceptation de « delete » à distance : la suppression est LOCALE seulement (table locale, rien n'est envoyé). Les accusés reçu/lu sont des trames éphémères signées, pas des événements du journal.
- Chiffrement : session TLS ; pour les données stockées ou relayées utilise AES-256-GCM (jamais CBC). Supprime MessageCrypto (AES-CBC non authentifié) ou remplace-le par une version GCM réellement utilisée.
- Nouveau contact par IP (algorithme demandé) : page Nouveau contact : saisie IP:port (ou choix dans « Appareils à proximité » détectés par annonces UDP signées, broadcast 45454 et multicast 239.255.42.99). Connexion, défi-réponse, puis : (1) si l'identifiant (hash de la clé) existe déjà dans la base : associe cette connexion au contact et à la discussion existants (nom, photo, historique), met à jour son adresse, reprend la conversation ; si la clé reçue diffère de celle enregistrée pour cet identifiant : ALERTE BLOQUANTE (« La clé de ce contact a changé »), rien n'est accepté ; (2) sinon ouvre une discussion TEMPORAIRE « Inconnu · <IP> » avec bandeau « Enregistrer ce contact ? » : Enregistrer = copie sa clé publique, demande un nom, récupère sa photo (par hash, via le transfert de fichiers) et l'affiche, empreinte à vérifier ; Ne pas enregistrer = la discussion reste marquée « non enregistrée », avec Enregistrer / Bloquer / Supprimer. Si l'IP d'un contact change, il est retrouvé par son identifiant lors des annonces ou d'une connexion (l'IP n'est qu'une adresse, jamais l'identité). Découverte manuelle IP:port toujours disponible (réseaux virtuels, WiFi qui filtre le broadcast). L'IP automatique vient de P3.
- Écoute robuste : port TCP configurable (par défaut 5000), message clair si le pare-feu Windows bloque, journal réseau sans contenu.
Autotests (transport simulé puis boucle locale) : défi-réponse valide ; signature falsifiée, mauvais identifiant, nonce rejoué, clé qui change = refus ; trame trop grande ou tronquée sans plantage ; fragmentation TCP (un message découpé en 3 lectures arrive entier) ; message d'auteur usurpé rejeté ; « delete » distant ignoré ; association d'un contact connu à une nouvelle IP ; contact inconnu temporaire puis enregistrement (clé, nom, photo) ; alerte de changement de clé.
